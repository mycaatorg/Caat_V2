# Owner community-content removal — PROD-87

People who leave private groups must still be able to remove their own earlier content. Keep group/post/comment SELECT policies unchanged: this feature must not reveal group names, rosters, peer text, reply counts, votes, or membership history. No membership or request records are changed.

Add `/communities/your-content`, reachable from the community header, listing only the signed-in author's own posts/comments with their own text excerpt, creation date and removal status. A narrow security-definer list RPC returns at most 21 rows (20 plus next-page sentinel), using stable created_at/id/kind ordering and a bounded page parameter. It returns no group or parent metadata. Treat excerpts as text, never raw HTML. The removal action accepts kind (`post` or `comment`) and UUID only, derives owner identity from auth.uid, and never takes an owner argument.

Removal preserves thread structure unconditionally. For a post, replace text with `[Removed by author]`, clear all attached result/score/poll/resume/major/university data, set anonymous true, revoke any shared resume, and mark `is_removed`. For a comment, set existing is_deleted true and content `[deleted]`. Other authors' replies remain untouched. Keep row/author identity for account cleanup and authorization; the UI explains that a placeholder and existing replies remain. It cannot remove copies already saved by others. Existing post-delete behavior is outside this feature.

Removal locks the owner row and is atomic. Missing/foreign IDs have the same failure result; a repeated removal of the owner's placeholder succeeds. Prevent stale edits from restoring removed content using database triggers: immutable redacted fields on removed posts; deleted comments cannot become active or regain text. Non-content changes needed by moderation remain permitted. Direct inserts/updates cannot create a removed post containing payloads (check constraint). Existing read RLS remains untouched, including after leaving or rejoining. Post deletion cannot resurrect shared copies because PROD-97 consumes publication UUIDs.

Use existing Next.js server actions and Supabase clients, no new dependencies or service-role application path. Add authenticated management UI with confirmation, disabled pending buttons, bounded requests, visible error/retry and success state; no optimistic removal before server success. Preview only the author's own excerpt, and do not navigate to inaccessible groups. Paging retains stable ordering because removal does not delete rows.

Verification: synthetic real DB tests for former-member/owner/nonmember/anonymous, owner list bounds, repeated removal, peer-reply preservation, draft/share separation, immutable redaction after rejoining, unchanged membership and no private reads. Unit tests for action validation/failure and UI confirmation/error/retry; browser journey leaves a private group, removes post/comment in management, and verifies the remaining member sees placeholders with replies. Full unit/type/lint, CI production journeys, one fresh independent review plus actual Claude, production metadata preflight and migration/ACL postflight, exact-main deploy/CI/auth health gates. Human pilot PROD-81 remains separate.
