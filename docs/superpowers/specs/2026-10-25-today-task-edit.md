# Edit personal tasks on Today — PROD-170

Students must be able to correct the wording or due date of a saved personal task without deleting and recreating it. Add an Edit action to each Today to-do, including the focused list. Reuse the established dialog and explicit opener focus reference. Text and optional date editable; priority and completion remain unchanged.

The editor begins with the selected row's current text/date. Require 1–1000 trimmed characters and a real optional calendar date. A save waits for a confirmed owner-scoped returned row before updating Today state. Match the original text/date as optimistic concurrency conditions; a deleted or externally edited row returns a clear conflict message, preserves the local draft and offers a reload-current action (with an explicit button, never discard automatically). Reload reads only the same owner's same task and updates the draft; missing record says removed and offers close. Completion may change independently and must never be overwritten by editing text/date. No generic edit API silently succeeds on zero rows.

While saving, preserve focus on the submit action with aria-disabled and a synchronous guard. Block close during pending write but bound the save to 30 seconds with abort support. Preserve draft after errors. Loading latest details is also bounded and cannot overwrite a newer interaction. On success update the matching row, retain completion and priority, close dialog, restore opener focus, refresh server data. Keep the list order stable during this edit session to avoid losing the opener. If a row has a pending completion mutation, disable Edit; a modal prevents accidental toggles while editing. Existing Undo actions must preserve edited text/date.

One additive SECURITY INVOKER RPC (edit_personal_task) keeps original text in a POST body rather than a URL, so long multilingual tasks remain editable. Existing table grants and owner RLS remain authoritative; no new tables or dependencies. Owner-filtered SELECT and invoker RPC UPDATE using browser role. No source requirement or application status mutation. Unit tests cover owner/conflict filters, zero rows, invalid input, failures, focus, pending action and completion/priority preservation; actual desktop/mobile journeys edit text/date, reload Today to verify, simulate write outage and stale original edit. Claude and independent review plus exact-head CI and production verification required before Done.
