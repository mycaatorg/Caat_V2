# Community resume sharing — PROD-97

Attach an explicit, immutable shared copy to a new community post. The composer shows the exact safe representation and requires a checkbox acknowledging its audience and any personal details. Public-feed/public-group posts are visible to signed-in readers; private-group posts inherit membership/creator access. Anonymous authors are warned that resume contents can identify them. Existing attachments have no shared copy and show an honest unavailable message; they never unlock private drafts retroactively.

The server reads only the owner's resume, renders the published mode (never the inactive draft or arbitrary structured metadata), and sanitizes HTML to basic formatting and safe links. A bounded DTO contains title and ordered section labels/HTML only. Preview and reader use the same responsive full-content renderer, including every section. The client sends the previewed frozen DTO; the server validates and sanitizes it again. A narrow transaction creates the post and share atomically, with a stable request UUID for safe retries. Draft RLS remains owner-only. The share table is owner-readable/exportable and owner-deletable; cross-user reads use a post-scoped RPC checking authentication, visibility, hidden state and blocks in either direction. No public or anonymous resume read.

Owners can remove a shared copy even after leaving its group. Post/account deletion cascades. Draft deletion does not erase an already explicitly published copy: the composer explains its independence and removal control. Readers recheck on focus/visibility and every 30 seconds; clear content on hidden tabs, denied/error responses and replacement. Revocation cannot retract copies already seen or saved.

No widening of resume/section policies. No service-role use in application actions. No backfill of historical posts. Existing basic formatting is retained, arbitrary CSS, images, embeds and active attributes are removed. The preview makes this visible before consent.
